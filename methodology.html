Methodology

The Signature Experiment Solver · SOLVER-ENGINE-V1 · record standard JAH-EXP-RECORD/1.0

What "solved" means

A solved experiment is a complete, structured, solver-generated record: question, hypothesis, null hypothesis, variables, materials, procedure, a three-trial Universal Matrix, measurements, findings, results, and conclusion — computed deterministically from a built-in mathematical model.

Solved ≠ performed. Solving an experiment here means the computer ran its model of the experiment. It does not mean anyone went into a laboratory, mixed chemicals, or measured anything physical. Every record carries this distinction as machine-readable fields, not just as a disclaimer.

The four statuses on every record

FieldValue on archived recordsMeaning
statusSOLVER-GENERATEDThe record was produced by the solver engine, not by a human author.
simulation_statusSIMULATEDEvery number is computed from a built-in model.
physical_statusNOT-PERFORMEDNobody physically performed this experiment to make this record.
measuredfalseNo real measured data is attached. Adding your own measurements flips the record to data_status: MIXED — the simulation values are kept and never overwritten.

Every number also carries its model (equation provenance), seed, assumptions, and units. A value quoted without its model is an ungrounded value. Missing information is reported as NOT RECORDED — never invented.

Determinism

Same solver type + same seed + same parameters = the same record, on any device, forever. Seed algorithm FNV-1a-32, PRNG mulberry32. Engine versions are immutable: SOLVER-ENGINE-V1 stays reproducible; new behavior becomes V2. Full specification: docs/DETERMINISM.md; permanent test vectors: docs/test-vectors.json. Any record can be re-solved in the browser and its content hash compared with the published hash (?verify=JAH-EXP-000123).

Permanent IDs

  • Experiments: JAH-EXP-###### — assigned once, sequentially, never reused, never reassigned. Canonical URL: ?exp=JAH-EXP-000123.
  • Solver types: JAH-EXP-TYPE-###### — 240 types in catalog order, A–Z browsable.

Safety classification

Every record carries a machine-readable safety_level, assigned by a deterministic rule-based classifier (same type → same level, always):

LevelMeaning
SAFE-EDUCATIONALOrdinary classroom-safe material.
ADULT-SUPERVISIONYoung scientists should have an adult present.
CAUTIONHeat, flame, chemicals, electricity, or projectiles involved — read the safety note first.
HAZARDOUSToxic or severely harmful materials in the topic — treat with full precautions.
SIMULATION-ONLYReserved for topics that must never be physically attempted.
DO-NOT-PERFORMTriggered only when the request itself asks for something dangerous or illegal. Answered with a pure-simulation disclaimer and no instructions, never with a procedure.

Archive integrity

One authoritative file — experiment-manifest.json — holds the single true count. Every counter on the page, the API feed, and the sitemap derive from it; the build fails on any disagreement (see code/qa/check.py). Content hashes for every record ship in data/hashes.json.gz.

Data & honesty

All experiment content is solver-generated from original models — simulations, not measurements. The archive grows by scheduled generation runs; records are never edited after creation. Corrections, when needed, are appended as new versioned entries, never silent edits.
